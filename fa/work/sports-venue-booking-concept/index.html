پلتفرم چندمجموعه‌ای

اگر هر باشگاه یا مالک قرار است پنل، قیمت‌گذاری و ظرفیت مستقل داشته باشد، Scope از یک سایت شرکتی فراتر می‌رود و باید به‌عنوان محصول چندفروشنده طراحی شود.

  • نقش‌ها و دسترسی‌های مستقل
  • تسویه و گزارش تفکیکی
  • قوانین ظرفیت پیچیده‌تر
  • معماری و بودجه مجزا
2026 technical baseline

پشت رابط ساده، چند تصمیم فنی حیاتی وجود دارد.

هدف این است که تجربه برای مشتری ساده بماند، ولی موجودی سانس، پرداخت و مدیریت از ابتدا قابل اتکا طراحی شوند.

01

CMS قابل مدیریت

وردپرس با قالب/بلوک اختصاصی برای محتوای ۱۵–۲۰ صفحه؛ منطق رزرو در ماژول جدا تا تغییر ظاهر، رزروها را شکننده نکند.

02

رزرو اتمیک

ظرفیت باید روی سرور نهایی شود؛ Hold کوتاه هنگام پرداخت، Idempotency و قفل منطقی مانع Double Booking می‌شوند.

03

پرداخت و پیامک

تأیید پرداخت از Webhook معتبر، ثبت وضعیت تراکنش، Retry کنترل‌شده و پیامک تأیید/یادآوری؛ نه اعتماد به برگشت مرورگر.

04

سرعت، SEO و دسترس‌پذیری

Core Web Vitals، WCAG 2.2، صفحات LocalBusiness/SportsActivityLocation، HTTPS، لاگ خطا و Backup جزو Definition of Done هستند.

مرحله دوم، نه MVP:PWA نصب‌شونده، رزرو تکرارشونده، عضویت، کد تخفیف، Waitlist، Split Payment و دسترسی هوشمند می‌توانند بعد از تثبیت جریان اصلی اضافه شوند.
